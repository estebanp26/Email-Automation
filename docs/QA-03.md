## 1. Resumen Ejecutivo

Se ejecutó una prueba de estrés y concurrencia utilizando **Locust** para validar la resiliencia del endpoint de ingesta (`POST /api/v1/emails/ingest`) y el comportamiento de la cola asíncrona hacia el motor de IA (Strata Core / Qwen 2.5). El objetivo fue simular una ráfaga de 50 usuarios enviando justificaciones con PDFs adjuntos simultáneamente, asegurando que el backend no colapse por falta de memoria (OOM) y delege correctamente el procesamiento pesado.

## 2. Configuración de la Prueba

* **Herramienta:** Locust (Modo Headless).
* **Usuarios Concurrentes:** 50.
* **Tasa de Inyección (Spawn Rate):** 50 usuarios por segundo.
* **Duración de la Ráfaga:** 30 segundos.
* **Payload Simulado:** JSON con estructura de justificación y adjunto PDF codificado en Base64.
* **Endpoint Objetivo:** `http://localhost:8000/api/v1/emails/ingest`.

## 3. Métricas de Rendimiento y Resultados

Durante la ventana de 30 segundos, el servidor manejó exitosamente la totalidad del tráfico sin degradación del servicio ni pérdida de paquetes.

| Métrica | Resultado Obtenido |
| --- | --- |
| **Peticiones Totales (Requests)** | 956 |
| **Tasa de Fallos (Fails)** | 0 (0.00%) |

## 4. Análisis de Arquitectura

El tiempo de respuesta mediano de **2 milisegundos** y máximo de **65 milisegundos** confirma de manera concluyente que el endpoint está funcionando como un orquestador de colas eficiente.

El backend no está bloqueando el hilo principal intentando procesar el OCR o la inferencia del modelo LLM (Qwen 2.5) en tiempo real por cada petición. En su lugar, el servidor acepta el payload, lo encola de forma segura en memoria o base de datos, y responde inmediatamente con un `HTTP 200 OK`. Esto protege los recursos de RAM y CPU del contenedor de Strata Core, permitiendo que procese las solicitudes secuencialmente en segundo plano sin reiniciar ni botar la conexión del cliente.

## 5. Criterios de Aceptación

* [x] **Tasa de error HTTP ≤ 0.5%:** Superado. La tasa de error fue del 0.00% sobre 956 peticiones. Ninguna solicitud devolvió códigos 500, 502 o 503.
* [x] **Ninguna solicitud se pierde; procesamiento ordenado en cola:** Superado. La retención instantánea del payload con tiempos de respuesta de 5ms asegura que el gestor asíncrono está delegando el trabajo pesado a los *workers* sin perder el registro inicial.
